**生效时间**：2026-10-15。**范围**：视觉、建模、材质、物理与生产、操作、NPC、世界模拟、存档、研究、性能、交付全过程。原有 `ENGINEERING_QA_RELEASE_POLICY.md` 负责审核，本文件负责**从开发第一分钟就遵守的制造方法**。这不是“目标已达成”的证明。

## 0. 定义作品质量：产品规格先于动手写代码
所有工作必须先产出一张**产品规格卡**并进入版本管理：模块ID、玩家场景与具体可见变化、参考标准（截图来源/许可）、测量单位、数据输入、主权状态的归属、依赖文件、交互路径、失败/回退路径、质量/性能预算、允许变化范围、源码负责人、对应自动化用例、实际Android验收方法、是否侵入原有存档、签名发布方式。**缺任何关键条目，状态为 DESIGN BLOCKED，不开始制作。**

示例：青瓦屋顶不是“生成780片瓦片”而是“从第三人称3–25米看得见正确坡屋顶、瓦脊与滴水；角色能从门进入；有施工来源；手机视觉稳定、不产生浮空和高亮噪声”。数量不代表品质。

流程：规格卡 → 风格板与技术调研 → 独立原型 → 主引擎集成 → 设计复盘 → 反例/边界测试 → 游戏内真实画面和操作 → Android长稳态与热态测试 → 独立审美复审 → 签名发布。**每一步不及格，返回其根因工序，不靠多堆内容补救。**

## 1. 美术和模型从工艺上保证品质（A/B/C/D/E/G）
### 1.1 先定义视觉语言
选定有许可的国风参考场景、地域、阶层、建筑制式、地理、季节和时代假设；固定色板、构图、镜头、昼夜色温。每种建筑先有平立剖与入口/排水/结构尺寸（米）；用户参考仅作艺术方向，不复制第三方版权素材。真实3D结构满足尺度、接缝、体积、邻近物体匹配，不能把贴图当几何。

### 1.2 每一个可视实体的交付单元
- **几何**：实体不悬空；有承重/围合/开口/交通路径；法线和拓扑正确；LOD至少近/中/远策略或说明为何复用；重要轮廓离远仍可读。
- **UV与材质**：每项有材质ID、UV0、真实像素密度、Albedo(sRGB)、Normal(linear且方向约定明确)、Roughness(linear)、AO/ORM清晰、材质可重复利用和合法来源；材质变体考虑使用状态、雨痕/灰尘/磨损依据，不使用无限随机噪声。纹理只有像素完整性通过不叫美术成品。
- **光照**：正午、阴天、傍晚、月夜与室内同色板；不把离线光追/桌面渲染冒充Android性能。墙瓦、地面和人物保持曝光一致。
- **镜头测试**：固定1280×720、3/10/25米、斜俯视/第一第三人称、遮挡与室内；白墙、青瓦、木构、柱础、地表、工人必须在正常游戏视距可识别。每种场景存参考/旧版/新版真实Godot和真实手机帧，附SHA、GPU、渲染器与画质档。
- **美术主观独立否决**：假塑料、灰黑大斜面、重复色带、单调地表、僵尸人、飘浮/穿模，一项存在就FAIL，哪怕所有脚本测试绿色。

### 1.3 人物生产（F）
首先用授权清楚的人形Humanoid骨架，不拿静态AI图充动作。体型/骨骼/权重/蒙皮/关节转角/衣裙物理/表情眨眼/口型/站走跑/劳作逐段制作。root motion与真实移动速度、脚接地、实体持物、打击与受击时序一致；远景骨骼LOD和更新频率分级。真实游戏中五分钟走跑转向录像无T Pose、脚滑、空手劳作、穿地，才给动画I/V PASS。

## 2. 操作体验标准：手机是主平台，不是桌面副产物
默认横屏、左侧移动摇杆，右侧滑动视角，独立交互命中区；触摸ID的手势所有权在按下瞬间确定，直到抬起不得从“镜头”误切成“交互”；UI弹层在进入时主动释放旧触摸、离开后可恢复；支持大屏/异形屏/不同DPI。按钮可点击区域与实际可见区域一致；永不强迫两拇指进入同一区域。操作调参由`engineering_contract.v1.json`的数据驱动，**需要真实采样**。

验收：冷启动、移动/转向/点NPC/门/施工UI、第一第三视角、近距离遮挡、室内、暂停恢复、来电后台/返回、断网/热更新失败；同时左摇杆+右滑+点击不冲突（计数必须为0）。触摸到真实反馈的p95目标 ≤100ms；真实设备未测不写合格。

## 3. 世界规则是唯一状态主权
延续现有`WorldState.entities / inventories / jobs / ledger`；渲染器、贴图、AI/LLM提示词、UI只读查询或提交合法的世界命令，不能悄悄创造物品、领取图纸、增加资产。每个人、建筑、工具、可使用物品有稳定ID和产权/产地/状态/损耗；大宗原料允许**批次ID + 数量与质量属性**，不为每粒土生成3D节点，仍可追踪消耗及合批来源。物理对象与渲染显示对象区分：LOD渲染销毁不等于世界实体消失。

每次库存变动要有唯一事务ID、前后库存、物料批次、操作人、场所、时间、工作工具及事件溯源。禁止负数、双重消耗、跨存档复制、失败工单产出成品、AI跳过手工阶段。保存原子写入、备份、CRC/结构版本兼容和故障注入；原有手机存档不可因更新丢失。NPC具独立目标与知识，但不能绕过资源产权和工时。

## 4. “物品树”实际应为可扩展的多输入多输出超图
严格定义为`生态来源→原料批次→半成品→组件→建筑/工具/商品`的**超图**，不是图片上的一条技能树。同一个原料按类别/含水量/颗粒/质量差异，经过不同设备与技能有不同工序和副产物。每条配方定义：稳定ID、材料种类和数量/单位、合格规格、设备、技能、温度或环境条件、时间、能源、产出数量与副产物、损耗去向、工人动作、危险、工艺解锁方式、图纸、检验点、资产可视化ID、版本兼容和材料溯源。

**样例链（v0候选，非现实工业配方）**：
- 黏质土 + 水 → 淘泥浆 → 淘洗细泥 + 筛余砂 → 湿砖坯 → 烧结青砖；
- 淘洗细泥 + 水 → 弧瓦坯 → 烧青瓦；两种烧制工序必须有燃料、窑炉与热过程；
- 石灰石 + 燃料 → 生石灰 → 熟石灰浆 → 与细砂、水共同配制抹面灰泥；
- 原木 → 结构梁 + 木屑余料；梁与瓦 → 屋面模块；砖与灰泥 → 墙模块。
原材料图谱公开代码见`game-source/data/craft/material_graph.v1.json`。首批物品24、配方14、研究6、图纸4，属于原型图谱，**不宣称制作物理真实工艺或国漫美术终版**。当前按一件物品的设计质量（g）检查配方投入=产出+损耗；真实化学计量、含水率、排烟/吸氧和批次质量变化未建模，后续必须逐项提升。

## 5. 研究、图纸、实验与玩家原创开发（独立知识层）
**知识**与**背包**分离：世界知识/角色掌握/地区行会工艺/图纸载体/个人笔记并存。获得图纸只说明知道结构，不赠送原料、工具或工人，也不意味着已掌握高级烧制技能。

解锁来源至少四类：
1. 师徒经验：工人重复做实物提升技术，但必须有实物工单。
2. 图纸/书籍：物理藏品有独立ID，可能损毁、盗取、买卖和复制，学习有前置知识。
3. 研究：真实观察样品、支付纸张与工时，完成研究任务后**由世界权限层写入**知识记录。
4. 自由实验：玩家选择材料、设备、参数、尝试加工，系统用成分、能量、质量、环境与设备支持度计算可能结果；失败也消耗成本。禁止输入“土+空气=神器”或通过改JSON创造质量/物品。

玩家的创新过程建议为`假设→实物实验单→材料锁定与扣除→环境/设备/安全检查→工时模拟→产物检测→复验→知识归档→可共享图纸版本`。配方候选应首先进入**隔离实验沙盒**，经过合法真实实验及设计审核后才写入玩家研究笔记；未经证实不计入正式世界公共配方。研究失败留日志和副产物/消耗；不能每次失败就免费重新发料。

## 6. 系统架构和扩容上限
物品目录（静态版本化资源），工艺目录（多输入多输出），图纸/研究图（有条件知识节点），实验求解器，世界工单处理器（唯一合法写路径），质量/材料批次系统，库存/产权溯源，视觉渲染绑定，手机操作/UI，持久化和版本迁移，均有各自职责。图谱索引`item→消费者 / item→产出工序`应预先建立；查询邻居不重扫全仓库。限制单次求解深度、批次和CPU预算；大世界NPC使用区块级/事件驱动仿真，离线区域不靠渲染器维持状态。

Godot 4.4.1可使用自定义Resource编辑资源类型，受信任的版本化JSON作为可审计内容源并在构建时验证/导入（参考Godot官方Resource文档）。固定资产ID、配方版本号与migration map，旧档的原有`WorldState.RECIPES`永不被新目录静默覆盖；先通过“读取/查询/预览”式适配器，再由权威世界状态模块集成新工单；**不得另建第二套背包**。

## 7. 数据调教系统不是脚本改两个参数
工程参数由`engineering_contract.v1.json`定阈值、允许区间、依赖指标和步幅；`tools/tune_data.py`读取真实镜头/触摸/模拟/Android性能证据，独立评估并提出**有上限的小步候选数值变更**（例如拉开右半屏镜头操作边界或减少远景密度）。不得自动修改游戏、提高作弊额度、虚构测试、降低QA门槛、自动把审美标为通过。所有调参结果必须经历A/B实测，尤其视觉不能靠算法评分代替真正设计师判断。

实际成熟流程是**先找根因**：如果屋顶看起来像黑色大斜面，应调整构造/屋脊/瓦几何/色板/观察镜头，而不是把曝光调成极亮掩盖问题；如果NPC脚滑，应校正动画root motion而不是隐藏脚部；如果帧数下降，应定位地形、实例化、骨骼、阴影和过绘瓶颈，而不是简单关掉所有细节。

## 8. 明确的工程门禁/里程碑
- D0 规范冻结：设计合同、范围/反例、数据字典、引擎选择、主权和性能预算均版本化，QA验证合同不可被随意放宽。
- D1 最小可垂直切片：一份可溯源黏质土 → 实际筛泥 → 砖坯 → 窑炉烧砖 → 砌一段有图纸的白墙，同时有完整近景骨骼工匠和资源台账；独立材质/工艺原型通过不等于此项完成。
- D2 公开工程整合：旧WorldState保存与旧存档升级回归、Godot新旧同场景真实导入、Android性能；只有此阶段之后才能申请手机试玩版本。
- D3 扩展资源树：按批次质量/地域生态/技术等级增量扩展陶、木、石、织、金、药、食、符、阵、器、建筑与修仙工艺。每添加物品必须能解释来源、用途、物理/经济后果与渲染载体。
- D4 玩家研究与自由实验：受限实验沙盒升级为世界工单，失败支付材料，参数通过真实工艺模型求解；实验知识可被人类NPC学习、交易、保密，但必须维持世界公平与存档兼容。
