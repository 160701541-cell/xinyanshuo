# 苍岚·人生世界：自我迭代优化协议 v1.0

> 2026-10-20 生效。本文件把 AI 研发助手（DSH agent）的工作方式固化为**可审计的闭环**，用于"任何东西都要自己写提示词然后严格执行迭代优化"这条长期用户要求。
> **本文件是执行约束，不是任何任务已通过的证据。** 与 `docs/ENGINEERING_QA_RELEASE_POLICY.md`（Q0–Q7 门禁）、`docs/DEVELOPMENT_EXECUTION_RULES.md`（唯一仓库与交付目标）并用。
> 优先级：用户最新指令 > `DEVELOPMENT_EXECUTION_RULES.md` > `ENGINEERING_QA_RELEASE_POLICY.md` > 本文件 > 其余文档。
>
> **来源**：本协议把 2026-10-19/20 角色迭代（会话 c5c602a8）里临时长出来的"自判分闭环"固化成文字。那套做法当年只存在于单轮对话里，换环境即失效 —— 本文件存在的唯一理由就是让它可移植、可校验、可被别的 AI 或别的机器接着跑。

---

## 0. 为什么必须有这份文件

两轮用户原话确立了需求：

- 「严格按这些执行，然后还需要自我迭代优化」
- 「任何东西你都要自己写提示词然后严格执行迭代优化」

历史教训（真实发生过的返工）：

| 做法 | 结果 |
|---|---|
| 靠"感觉变好了"验收 | 同一人物反复重做十余轮，色板一度从 `#2E8B6E` 漂到高饱和薄荷绿，用户被迫指出"这怎么是裙子"、"脖子也有问题" |
| 只看单张正视图 | 侧面/背面穿帮（袖是方盒、金襟像木棍、头发像头盔）在正视图上完全看不出来 |
| 用 CI 绿灯代替美术判断 | 引擎技术 QA SUCCESS 但用户判定 HQ 美术 FAIL |
| 把方案留在对话里 | 会话结束即蒸发，换环境必须从零重长 |

**结论：判断必须数值化、出图必须固定机位、方案必须入库。**

## 1. 闭环八步（每轮必须完整走完，禁止跳步）

| 步 | 动作 | 硬性产物 |
|---|---|---|
| R1 | **锁目标**：本轮只允许一个可量化目标（不许"顺便美化一下"） | 目标句 + 参考图/风格锁路径 |
| R2 | **参数化生成**：提示词与生成脚本参数化，同参数必须可复现同一结果 | 脚本路径 + 参数表（JSON 或 md 表） |
| R3 | **固定机位出图**：至少四视图（正/侧/背/三视角），同机位、同光照、同分辨率 | ≥4 张 PNG，命名含轮次编号 |
| R4 | **自动量测**：从画面/网格提取数值，禁止肉眼估计 | `metrics` 数值对象 |
| R5 | **自判分**：逐项比门槛表，输出 PASS/FAIL/BLOCKED | 判分表（见第 2 节） |
| R6 | **归因**：未过时判定问题出在哪一层（拓扑 / 材质 / 色板 / 描边 / UV / 光照 / 部件比例） | 一句话归因，须与 R4 数值对应 |
| R7 | **最小改动回炉**：一轮只动**一个变量族群**；禁止同时改色板+拓扑+光照 | diff（文件级）+ 下一轮编号 |
| R8 | **入库或记录失败**：过 → 提交截图/参数/源码/底模；未过 → 失败也必须留痕（含本轮数值） | 台账轮次文件 + git 提交 |

**禁止跳步**：没有 R3 的图，R4/R5 一律非法；没有 R4 的数值，R6 的归因一律视为臆断。

## 2. 指标与门槛表（数值化验收，禁止形容词）

下列门槛由 `tools/self_iteration/check_round.py` 自动执行；"测法"一栏写明怎么得到数，得不到就必须标 BLOCKED，不许填估计值。

| 指标 | 测法 | 门槛 | 适用 |
|---|---|---|---|
| 主体/背景明度差 ΔL* | 主体掩膜与背景区域在 CIELAB L* 的均值差 | ≥ 25 | 全部角色四视图 |
| 点缀色面积占比 | 点缀色相像素 / 主体像素 | 3% – 8% | 服饰 |
| 主色漂移 ΔE00 | 与风格锁色板的最近色距离 | ≤ 6 | 服饰/发/肤 |
| 屏幕空间描边宽度 | 描边像素数 / 轮廓长度 | 1.5 – 2.5 px | 全部 |
| 四视图可辨部件数 | 正/侧/背三图中可独立辨认的部件（脸、发、领、袖、襟、带、靴…） | ≥ 5 | 全部 |
| 三角面数 | 网格统计 | 见当轮预算（移动端） | 角色/道具 |
| 部件比例（头:躯干:腿） | 包围盒高度比 | 与目标骨架比偏差 ≤ 10% | 人体 |
| 颈/关节穿帮 | 相邻部件接缝处空隙像素 | 0（无可见裂缝） | 人体 |
| 渲染帧时间 p95 | 真机/引擎采样 | 见当轮性能预算 | 正式候选 |

**风格锁**：色板与材质档位取自 `tools/asset_factory/CANGLAN_WORLDX_STYLE_LOCK_V2_HQ3D.md` 及角色专用 `tools/character-pipeline/docs/CHARACTER_SPEC.md`；改风格锁属于 R1，不属于 R7。

## 3. 每轮台账格式（固定字段，机器可校验）

每轮产出一个 JSON，路径 `tools/self_iteration/rounds/round-<编号>.json`，字段固定：

```json
{
  "round": 1,
  "date": "2026-10-20",
  "target": "主角人物建模：脸/颈/发/服饰 四视图达标",
  "branch": "art/qinglan-rig3-world-cloth",
  "commit": "<40位SHA>",
  "changes": ["只改了一个变量族群：颈部比例"],
  "renders": ["shots/round01_front.png", "shots/round01_side.png", "shots/round01_back.png", "shots/round01_three.png"],
  "metrics": {"delta_L": 49.3, "accent_area_pct": 5.2, "delta_E00": 4.1, "outline_px": 2.1, "parts_readable": 6, "triangles": 41200, "head_torso_leg_ratio": [1,3,4], "neck_gap_px": 0},
  "verdict": {"technical": "PASS", "aesthetic": "PENDING"},
  "attribution": "本轮未过项归因于…",
  "lessons": "本轮学到的、下一轮必须继承的结论",
  "next": "下一轮唯一变量"
}
```

校验：`python3 tools/self_iteration/check_round.py tools/self_iteration/rounds/round-<编号>.json` —— 逐项打印指标 vs 门槛、给出 exit code。

**verdict 三档语义**（不得混用）：
- `technical`: 引擎能跑、网格/材质/贴图合法 —— 由脚本判定。
- `aesthetic`: 审美批准 —— **只能由用户/人工判**（见第 5 节）。
- 任何本轮没真跑的项写 `BLOCKED` + 原因，禁止填 PASS。

## 4. 停损与换路

同一门槛**连续 3 轮无改善**（改善定义为指标朝门槛方向移动 ≥10%）即判定"该路线失败"：

1. 写 `LESSONS`：写清试了什么、为何无效（要具体到机制，不许写"效果不好"）；
2. 换**工具层**，而不是原地微调：Blender 手工/程序化 ↔ Godot 程序化生成 ↔ 有许可证的真实 GLB/扫描资产 ↔ AI 图像端；
3. 换路线后重新走 R1（目标与门槛可能变），并把失败路线记入台账，禁止删除痕迹。

**禁止**在同一路线连续磨 5 轮以上还宣称"在迭代优化"。

---

## 5. 自批审美的禁令

依据 `ENGINEERING_QA_RELEASE_POLICY.md` 第 1 节：

- AI **无权**给出 `aesthetic: PASS`；只能给 `technical` 与指标数值。
- 禁止写"已通过美术验收""已达到国漫级"等需要人工批准的结论。
- 用户说"你觉得满意就行"**不等于**审美已批准，只等于免除询问义务，闸门依然由用户验收。

## 6. 跨环境接续（用户会把仓库拿到别处跑迭代）

要让另一个 AI / 另一台机器 clone 后直接接着跑，仓库必须自足：

1. **产物全入库**：源码、参数表、四视图、每轮台账 JSON、底模、踩坑记录一并提交；中间产物不许只留在本机。
2. **一条命令复现**：生成/渲染入口写成脚本（`.gd` / `.py` / `.mjs`），带默认参数可无交互运行。
3. **环境依赖显式化**：所需引擎与版本在文件头注明；本仓库当前已知可用：Godot `4.4.1-stable`（arm64 于 `/root/godot/`）、Blender `4.0.2`。
4. **缺依赖的写法**：写 `BLOCKED: 缺少 <工具/版本>`，并继续做同环境内能做的量测；**绝不**降级为"用文字描述画面"充当出图。
5. **分支纪律**：每轮提交在既有工作分支上（默认 `art/qinglan-rig3-world-cloth` 或当轮声明的分支），不擅自改 `main`、不改 `android-preview/latest.json`。

## 7. 明确禁止的违规示例

| 违规 | 为什么 |
|---|---|
| 只提交文字总结，不提交图 | R3 缺失，无法复核 |
| 指标填"目测约 40" | R4 要求可复现测法 |
| 一轮同时改色板+拓扑+光照 | 违反 R7，无法归因，等于浪费一轮 |
| 未跑引擎却写 PASS | 违反交付规则第 6 条（真实QA和证据） |
| 把方案留在对话里 | 本文件存在的理由 |
| 用 `main` 直接承载未验证实验 | 破坏正式线 |

## 附录 A · 门檻操作化修正案（2026-10-20，第 3 轮起生效）

第 1 节的门槛表是**目标**，第 2 节的每一条还必须有**可复现的操作化**（R4 仪器）。操作化本身会
出错，出错就换，但**必须留痕**。已发生的修正：

| 门檻 | 原始操作化 | 问题 | 现行操作化（仪器版本） |
| --- | --- | --- | --- |
| 点缀色面积 3–8% | 色相 35–60° 判金边 | CIELAB 下金黄≈80°、肤色≈68°，金边被全判成肤色（实测恒为 0.01–0.14%） | **v2** 按彩度分离：金 ≥28 / 肤 12–28 |
| 颈缝 = 0 | 同行内被主体左右夹住的背景像素（v2）；被包围的背景孔洞（v3）；金边上沿以下的夹缝皮肤（v4） | 头部特写的头/肩天然凹槽、以及"领口以上正常可见的颈部"都会被误判为穿帮；连续两轮无改善 | **第 3 轮换工具层**：几何口径 `body_breach_verts`（身体顶点满足 `(x/rx)^2+(z/rz)^2 > 1` 的数量）= 0；像素 `neck_gap_px` 降为辅助回显 |

换层规则（与第 1 节停损规则配套）：**同一门檻连续两轮无改善即开始排查操作化**；连续三轮无改善
必须换工具层，并在台账 `lessons` 与本文档附录留痕。禁止的做法：悄悄改判据让数字变好看而不留痕。
