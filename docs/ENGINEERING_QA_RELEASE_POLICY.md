# 苍岚·人生世界：工程质量门禁与美术验收规范 v1.0
> 2026-10-15 生效。目标是减少“先堆功能再返工”；不能把单元测试、模型数量或CI绿色冒充游戏里达到美术目标。适用于Godot 4.4.1、Terrain3D、Android、增量PCK和完整APK。**本文件是执行约束，不是现有任务已通过的证据。**

## 1. 功能完成的定义（不可合并状态）

每个交付项必须记录 S源码、U单测、I主工程集成、V实际引擎画面、P设备性能、D手机安装/运行、R签名发布、A审美批准；每项填写 PASS/FAIL/BLOCKED/NOT_APPLICABLE 及提交SHA、引擎/驱动/设备、产物哈希、测试日志、负责人、日期。**任一适用项没有PASS，一律不能写“完成/已进入玩家游戏”。** 
- 对美术样板而言：S/U PASS只能叫“技术研究资产”；V PASS只证明渲染存在；A必须独立人工审图，不得由生成器或CI自我批准。
- 对手机测试候选而言：原游戏集成I、存档数据、更新安全、签名与发布均通过才能让用户手机验收D；D结果未回报前写“待玩家验收”。
- 坚持原WorldState主权：任何展示资产不得改变实体唯一ID、库存/产权/交易台账、用户旧存档。保留旧档/备份/异常回滚。

## 2. 开发之初必须通过的设计审查
每个功能开工先给出：玩家能看见的变化与参考、真实数据流及依赖、可量化验收、正常/极端/失败场景、成本与手机性能预算、资源来源授权、不可接受的视觉缺陷和安全边界。
架构优先遵循现有主世界与已有工作分支；禁止新增第二套库存/玩家控制器/假NPC，禁止静态效果替代角色骨骼动画，禁止模型仅按数量验收。
原型与正式资产必须隔离：正式资产须有完整UV0、实际mesh拓扑、合理texel密度、BaseColor、Normal、Roughness与AO/ORM规则、变体及移动端LOD记录；导入后真实场景观察，不接受纯PNG预览充当游戏效果。

| Gate | 自动检查的真证据 | 不通过即阻止 |

**自动测试对视觉风格没有独立审美能力。** 同一机位人工画面检查是单独硬门禁；形式化PNG质量指标仅能检出坏图、接缝、平面法线、通道错误，不能把普通程序纹理提高成国漫级专业美术。

## 4. 美术质量否决项
任何一个成立，即停止新增内容，先返修根因：
1. 从预定游戏镜头看仍是明显“玩具沙盘、土黄塑料/纯色块、整片黑屋顶、满屏均一地表”；
2. 墙角未收口、建筑浮空、屋檐没有构造、瓦形和瓦缝在正常视距不可读；
3. NPC T-Pose、脚滑、穿地、拿空工具、库存未变化就施工；
4. 巨大蓝灰三角面穿屏、水面断崖、镜头进入屋顶、HUD与视角拖动冲突；
5. 实机同场景下超出目标draw/triangle预算，无诊断、LOD或差异记录；
6. 截图无真正引擎来源、无硬件信息/版本SHA，或拿概念图当手机效果。
参考画面、实际Godot帧、Android实帧必须标注并并列。审图不通过，不能宣称美术完成。

## 5. 自动化测试必须证明“它能发现坏东西”
- 生产正确样本同时插入至少一种故意损坏样本：损坏CRC、重新哈希的平面贴图、法线翻转、贴图接缝、路径穿越、无关文件混入；测试须真正FAIL，而非测试文件存在。
- 原材料库采用**独立**解析器直接读取RGB像素/CRC/PNG载荷，不使用生成器的内部函数判断其输出，防止同源错误互相遮蔽。
- 每轮CI产出可审计JSON指标、原始日志与原始截图。不得删测试/放宽阈值来追求绿灯；修改预算须说明设备证据及用户可见代价。
- 发布管线必须引用同一已验收commit的质量产物；从实验ZIP直接复制到正式PCK、跳过Godot导入或只看filename均为失败。

## 6. 测试等级与性能基线
初始参考目标不是跨手机的绝对承诺：中档手机优先稳定30fps（p95帧时间<=33.3ms），适配机型争取60fps；**Android实测前均为待验证**。Draw Call与三角面预算先参考HUD既有200/150000提示值，出现超标先做分析，不因单帧FPS看起来高而忽略热降频。至少记录连续15分钟、前后温度/内存及p50/p95，并分清GPU不可读时的数据缺失。

## 7. 当前已知阻塞（真实状态）
- 公开仓库只有独立P1材料试验脚本，**没有经全量审计导入的完整Godot原游戏**。
- P1程序贴图虽然可以通过离线像素QA，仍没有原游戏Godot实景A/B、Android实景、人工审美批准，不能标“国漫终版”。
- 私库分支已有已知P0级大面片穿屏与P1级人物/建筑缺陷，需定位来源，不能借发新纹理覆盖。
- 官方APK dev.176 / PCK rev167完整性检查PASS只证明旧包未损坏；**新版本未构建、未签名、未交付**。公开迁移M04–M08仍待完成。

## 8. 返工治理
发现失败写“可复现步骤→根因假设→隔离实验→确认根因→最小修复→回归与反例→实景复查”，每个缺陷保留截图及复现种子。优先修一处根因，不靠堆新资产遮盖缺陷。工作日志只记已发生的证据，严禁将将来任务写成PASS。
