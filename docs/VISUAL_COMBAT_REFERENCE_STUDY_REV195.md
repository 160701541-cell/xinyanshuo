### 为什么参考图看起来「是小方块却更细致」
- 不是三角形数量本身决定品质。真正显著的是**在各层级都统一控制的视觉语言**：大剪影/人物比例→中尺度服装分层与建筑造型→小尺度格状叶片/发束/地砖→受控法术像素碎块；人物脸部保持干净而不是被粗糙纹理覆盖。
- **候选工艺 A：体素/微块模型**。适用于风格化发丝、叶片、饰物与法术碎片，但手机场景若每块独立Mesh会极其昂贵；必须合并网格/贴图或 GPU instancing。
- **候选工艺 B：低模/中模角色 + 小像素贴图/不滤波像素纹理 + 清晰轮廓**。对现成 CC0 骨骼角色较易适配，可为衣服、面饰、头发做独立材质层级，避免把所有脸部变成粗糙方块。
- **候选工艺 C：HD-2D/定向精灵 + 真3D院落 + 特效的多层合成**。视角固定更便宜，但《苍岚》已经要求第三/第一/上帝视角切换，正式人物不能仅使用正面假二维立绘来欺骗各种相机。
- 单凭这三张**无法确认哪种工艺为原创作者所用**，应通过**同一个真实GLB角色/同一块院落**在当前原游戏的三个渲染方案试验对比 FPS、GPU时间和手机效果，选最终统一标准，不能口头直接把参考命名为「高密度体素」就算学会。

## 二、动作手感拆解：视觉特效必须追随碰撞帧

### 动作时间轴（制作目标，不代表参考作者的原始参数）
- 基础剑击全长 0.42～0.58 秒：前摇约80～150ms → 有效攻击帧90～160ms → 收招200～300ms。剑在前摇先有方向与蓄势，命中**必须来自真实近身碰撞/判定**。
- 格挡按住：进入格挡姿态，移动速度降低、消耗实际体力；成功格挡有火花与受击音，伤害减免遵守装备/耐久/姿态数据。
- 完美格挡：尝试以**80～120ms 可调时机窗口**命中时奖励短十字爆闪、蓝白冲击圈、短促 hit-stop 和可触发反击的真实状态；超出窗口按普通格挡处理。不能只看特效判断成功。
- 闪避：以**0.22～0.32秒**的可读动作表现，短距离移动真实角色，期间由状态系统控制短暂无敌帧，与地形坡度/水/障碍碰撞不冲突。
- 完美闪避：在敌方攻击的真实危险窗口内执行，触发短时慢镜感、人物位置残影；五道剑气须受到解锁进度/灵力、技能与装备约束，不允许凡人未经灵根检测突然无限御剑。
- 招式摄像机反馈：命中时40～70ms以内的克制hit-stop和1～3像素轻微冲击，重点强调瞬间阅读而不是整屏乱震。可调整强度，用户可关闭震屏。
- 表演层必须明确五个阶段：预警（telegraph）→蓄势（windup）→释放（active）→命中（impact）→恢复（recovery）。美术和规则系统共用**同一个事件时间轴**，不存在显示出剑击中敌人却判定0的情况。

### 图中蓝青御剑如何实现（不直接复制原创作品）
1. **真实技能实体**：解锁/修为/装备持有者ID/目标/投射方向/冷却/消耗灵力/弹道与命中结果由规则层决定，服务器或独立世界模拟可复演。
2. **剑身造型**：使用有许可的成品刀剑 GLB 或相同合法网格重复实例，不自己正式手搓原创主角/剑模型；统一青白亮边、深青柄、暖金少量装饰。10把御剑首选 MultiMesh/mesh reuse。
3. **VFX形体层**：内核亮剑→短弧拖尾→断裂式像素碎块→低粒子量冲击火花→命中后快速消散。色彩主轴青白/蓝青、对手火光偏橙、血量伤害红色，仅关键峰值使用高亮。
4. **真实光环境**：必要时局部短暂 OmniLight3D 照亮角色和石地；实际暗巷暖灯 + 冷色空气背景 + 剑光冰蓝。限制局部阴影灯数量，手机禁止同时大量 shadow-casting point lights。
5. **性能**：近景主角/敌人优先保留清晰轮廓，粒子/拖尾/闪烁按三档手动画质裁剪且不变更真实伤害判定。低档仍清晰表示「格挡成功」/「闪避成功」，只是特效简化。

## 三、3D场景和材质为什么有沉浸感
- **大尺度结构先准确**：庭院、真实地面铺砖、墙、门槛、石阶、檐、屋顶、灯笼，每个构件有真实功能/碰撞、NPC路径、住户和床位；不能用单张高质量庭院图片假冒可走院落。
- **中尺度重复与变体**：石砖瓦片是可重复小件/atlas，颜色和粗糙度变化有序、墙脚潮湿、台阶边磨损、不同木料深浅区分；落叶和灌丛自然成片但不遮关键攻击动作。
- **小尺度材质**：高质量贴图是法线、粗糙度、AO与色彩联合效果，不代表每块小石头真的多一堆三角面。建议真实物理材质 + 微弱贴图色差、控制 mipmap 和纹理过滤，近景角色脸部避免明显像素噪声。
- **构图与镜头**：第三人称/斜俯镜头可看到角色、对手及伤害区域；不是所有场景都一律上帝视角。战斗时人物脚底贴地、遮挡建筑透明/镜头碰撞，第一人称保留手/武器真模型。
- **昼夜光影**：白天深青绿＋暖阳/树影，夜晚蓝青环境＋橙暖灯笼，技能光只在关键帧达到峰值。现有 rev194 的地表/远雾改善不等于完成光影工业化。

## 五、游戏实装流水线（项目不可违反）
1. **视觉实验 V0**：先在原 Godot 场景里核实角色可显示、有脚步动画、真实中式院落地面与门槛可走；手机竖屏不作为原游戏正式测试，横屏遵守当前 UI/120Hz/三画质。
2. **近景角色 V1**：合法可动角色GLB + 鉴别清楚的面部/头发/服饰纹理 + 实际两机位（近景/第三人称）真实Godot截图；不能新建手搓正式角色。
3. **完整战斗 V2**：同一原游戏中对一个敌人实现**真实**普通格挡 / 完美格挡 / 闪避 / 完美闪避，100次输入和10种失误时机矩阵、体力不负数、敌人攻击命中、无敌帧逻辑、资源守恒；没灵根的角色先做凡人武学，不直接开放御剑。
4. **修仙特效 V3**：灵根检测/功法/真实法力系统接入后，才开放五剑、十剑列阵、剑气轨迹和法器消耗，视觉与碰撞/法力账本一致。
5. **画质与性能 V4**：Godot4.4 Mobile Vulkan真实引擎至少昼/夜/释放/格挡四机位截图；Godot软件Mesa只能算原项目/渲染自动QA，不能冒称一加 Ace5 Pro 真机效果。三档分辨率和手柄/触屏/120Hz不回归。
6. **正式交付 V5**：唯一公开repo、本游戏原APK176签名PCK、RSA/SHA256/HTTP Range、原APK本机热更新；每轮更新日志。无新原游戏真实改动、未通过Godot QA或签名检查不得发布。

## 六、视觉 QA 的硬门槛（以玩家感受为准）
- **立即看懂动作**：静态六格中，遮住文字仍能区分吸收/飞剑攻击/完美闪避/格挡，否则退回重新设计；
- **近景人物可读**：面部不是纸片、无僵尸姿态、能辨认发型衣饰、衣服与背景分离；真实角色存在场景中，不是UI插画；
- **特效不遮挡操作**：多粒子场景仍看得见玩家身体、敌人动作、生命/体力/灵力、实际攻击轨迹；
- **光线能落到物体上**：冷光照在深色衣服、暖灯照在木柱、光亮粒子照出地砖质感；不以全屏Bloom代替材质和受光关系；
- **连续三档**：普通不丢玩法反馈，高档保持清晰粒子，极致强化细节且不强制限制帧率；仅手机真机实测填写FPS/温度；
- **首个交付区域必须是可玩院落**：门开关、台阶通过、NPC居住、草树生态和修士动作皆有真实实体，不能只发参考级效果图；
- **不宣称作者方法**：截图所展示的「小方块/像素」美术观感并不足以证明其模型拓扑/贴图采样/渲染算法，后续学习保留独立验证记录。
