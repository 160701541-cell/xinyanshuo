# 仙凡·苍岚：本地大模型驱动对话与剧情演化 v1

> 源码分支：xianfan/android-embedded-llm-prototype。首选本机 Qwen3-8B Q4_K_M（若硬件不足可换4B），不需要 GPT 账号；独立 API 为自愿备选。任何 APK 构建成功不等于设备已验证 8B/14B 模型加载、速度与稳定性。

## 运行原则（模型只提案，世界规则算账）

玩家自由输入
→ 若是已支持的明确指令，世界引擎立即执行，省去一次8B推理。
→ 否则用本地模型辨识意图，得到规则引擎允许的动作候选。
→ 规则验证时间、体力、NPC是否在场、真实物品库存、资源再生、地图和灵根不可伪造约束。
→ 已提交的有意义生活事件触发单次「AI世界导演」推理，产生JSON剧情段落和一个预定义人生伏笔ID。
→ 世界引擎校验该伏笔的位置、前置条件和7日冷却，并持续在权威本地存档中记录其阶段与NPC真实意愿。
→ 剧情页面独立展示模型叙事（醒目注明不代替规则），NPC聊天页只显示对话。

## 手机上节省推理开销

- 只加载一份本地 GGUF，通过单个 NobodyWhoChat 顺序复用；不会给每位NPC重新加载一个8B模型。各NPC的短上下文在每轮重新构造，彼此不串台。
- 建议 n_ctx=4096（14B=3072，内存压力较低）；本机 n_threads=3，优先使用插件支持的 Vulkan GPU。
- Qwen3 `enable_thinking=false` 用于即时NPC对话、自由行动解释和短篇剧情；无需每次让模型思考上千token。
- NPC对话使用略高温度以避免机械重述，结构化动作使用较低温度。剧情按已结算的事实与伏笔候选生成。
- 已知的按钮和准确指令走本地规则；对话即使来自NPC弹窗，也走AI而不是固定台词。
- 默认「关键事件」时，换地图、耗时较大的行动或隔了一段游戏时间后才再生成故事，避免模型每帧、每点按钮都推理。
- 提供「关闭／关键事件／每次行动」三个强度；高品质每次叙事会显著增大手机发热、耗电及等待时间。
- 本地推理逐token返回，NPC文本在对话页逐步出现；提供「停止本轮AI生成」，仅完整生成的输出才提交存档。

## NPC长期记忆和真正的自主日程

- `dialogue_archive` 永久按时间追加玩家/各NPC原始对话，`npc_memories` 按姓名持久化索引；近期UI保留80条窗口，不删除后端原始对话。
- 使用玩家追问的中文字双字组合对旧对话做本地轻量检索，每次选择最多4条相关长期回忆+4轮近期连续对话；不需要额外加载向量embedding模型。
- 世界位置、日程、真实财物和血量是规则权威；旧对话只是当事人说过的**话**，不因此成为事实。
- NPC的生活进展仍按世界时钟和真实规则每日演算；家庭成员各有工作、情绪、学习、个人愿望与推进值。长期剧情伏笔可以把愿望加入NPC档案，但不立即授予财产、灵根和境界。
- `npc_life_events` 持久保存每天的本人位置、生活活动与愿望变化，供下一段AI故事使用。
- 已开放的支线每7个游戏日才可能继续下一阶段，最多20阶段；即使模型生成无效或冷却未到也不强行写入。

## 完整性、可观察性与验收

- 模型输出必须独立通过 `record_ai_story` 检查：预期世界时钟仍一致、地点条件满足、剧情长度可控、被明确禁止的假突破与凭空发财不得写入。无效伏笔自动降格为无机械效果的描述。
- 对话由 `record_ai_dialogue` 存档，来源标记 `local-gguf` 或 `api`。NPC不在现场不得模拟当面交谈。
- 模型出错、缺少规则、无效叙事归入可复制的本地反馈日志，API密钥不写入存档或反馈。
- 自动化测试覆盖：存档完整、92轮记忆归档仍可检索、跨NPC隔离、非法伏笔拒绝、正确时间锚点、NPC志向推进、流式UI、直接命令零模型调用策略、分离剧情与交谈。
- 自动测试在 GitHub Linux x86 环境运行，无法代表真正的Android 8B推理效果、耗电、温升、吞吐速度以及模型下载是否成功。上述设备试验未做时必须明示。

## 仍未完成

1. 在用户具体的12GB物理RAM手机上进行8B模型下载/推理性能实测及Android OOM防护。
2. 当前世界NPC主要仍是钱家三位亲人及少数已注册实体；尚无海量独立宗门NPC及千人社会模拟。
3. 本地世界导演目前只能推动白名单剧情伏笔。复杂战斗、宗门探索、婚姻、生育、技艺研究等必须先有对应规则才可真结算。
4. 进一步支持按玩家偏好动态剧本包、追加外部知识检索、跨存档回放和剧情阶段任务链。
