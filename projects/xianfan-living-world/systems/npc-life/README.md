# 系统级 NPC 人格／终生经历注册制度 v1

本制度对**任何登场的 NPC**生效，不是仅针对孙成明，也不是临时的聊天摘要。

- **世界永久身份键**：`campaign_id + npc_id`；同名不等于同一人；同一个世界不得重复ID。每个世界自己的角色档案存在 `campaigns/<战役>/npc_registry.json`；通用方法放在 `tools/npc_identity.mjs`。
- **不可随便修改的出生资料**：姓名、性别、出生背景（若已登记）、家庭、与他人的关系、年龄基准、固有ID、出处事件。初始已定但尚未证明的亲缘细节标记“未知”，不可猜。
- **人格不是单一固定标签**：稳定倾向（谨慎、好奇等）是**可用于行为决策的参数**，必须有已知事件或确定性初始化算法作依据。心境、信任、恐惧、恩怨、职业目标会根据发生的事件变化。人格维度缺数据则标unknown，不会凭空填满100分。
- **人生历程不可覆盖**：出生→工作→婚育→迁徙→友情／恩怨→修为→伤病→死亡，所有变化引用`EVxxxxxx`事件编号，按时间有序追加；过去遭遇和承诺不会随时间压缩而丢失。
- **知道什么与真实发生什么分离**：公开NPC档案仅写可获知身份、经玩家见证的事件和合理公开消息；秘密动机、灵根结果等必须存私密层，绝不能进公开GitHub。
- **NPC有自主权**：一个“喜欢冒险”的角色也能因为义务或害怕拒绝玩家，永久仇人亦不能无证据无限追踪。人格参数由规则引擎结算，而不是文本为了剧情反向重写。

每回合行动完成后，游戏数值存档／事件链优先，NPC档案按新事件**追加**记录，再更新公共剧情索引。每十轮人物摘要从档案索引生成，永久原始事件不可删除。

`tools/npc_identity.mjs`包含可复算的确定性基础性格算法、身份同步、经历追加以及一致性检查；未来新增 NPC 必须走同一入口。当前原有父、母、妹妹的三个固定ID和关系不能改动。

**测试状态**：初始系统化人格属于版本化生成的**本游戏设定**，不等于角色此前已经通过实际对话展现出的事实。生成性格也不会改动权威事件或玩家时间。

## 持久人格参数 v1.0（新增）

`tools/npc_identity.mjs`的`inherentTemperament(world_seed,npc_id)`对每位NPC自动产生可复算的**游戏内基础气质**（好奇、勤勉、谨慎、社交、合作、承压六维，35—65分），并逐个存入独立世界的`npc_registry.json`；一旦建档不得无凭据变化。**这些分数是程序生成的倾向，不是现实心理诊断或已经发生的经历**。事件化观察到的人格特点须有正式历史事件做来源；NPC可因环境、利益、社会关系而偏离基础倾向，不应按数字机械固定言行。

角色不应拥有玩家未得知的全知资料，未验证的天赋、秘密身份与剧情真相不会写在公开档案里。
