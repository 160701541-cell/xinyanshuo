# 从聊天第一世到原生 Android APK 的可验收迁移计划

日期：2026-10-25。**游戏研发方向，不是已经交付的新APK。**

## 关键结论
这局互动可作为**规则引擎端到端验收样例**，但不能把聊天里跑过的 `Node.js .mjs` 源码直接声称已是手机原生游戏。当前仓库独立分支存在浏览器ES模块原型和Android WebView壳；用户希望最终转为 **真正的可安装Android游戏、并避免HTML做游戏主体**。因此要迁出业务规则，保留可复算的世界状态与事件协议，优先原生游戏框架或Godot Android导出，且不改变另一个《苍岚》主项目。

## 阶段门禁（必须每项真实通过）
1. **核心引擎抽取**：把聊天期间所有 `tools/*_turn.mjs` 的物资、NPC、时间、种子判定、生态、交易抽象为可复用的注册动作系统；清理直接依赖Node `fs`/`crypto` 的平台接口。**此项未完成**。
2. **真正的世界循环**：独立运行玩家位置移动、NPC工作/进食/休息、生产消耗、跨日生态、鱼笼检查与资源再生/耗尽，不能只有“用户说一句→专用脚本改一个JSON”。**尚未完成**。
3. **确定性账本与回放**：全事件链SHA256、产权/金钱/物品库存、地点安全、状态重算一致性；回放本局EV000001之后的全部行动，并实现严格快照迁移。**部分已完成，回放未验收**。
4. **手机原生客户端**：建立Android项目（例如Godot 4.x）和触摸HUD、背包、地图、NPC对话、制作、世界时钟、存档、声音/美术资源。不是WebView包装网页。**尚未完成**。
5. **接入AI但让AI不能乱改数值**：在规则引擎API前设置动作命令白名单和数值检查；先内置无联网可玩剧本/确定性NPC状态机，再提供可选云API或手机端量化小模型下载。AI只建议对话和意图，核心数值世界由独立引擎结算。**尚未完成**。
6. **发布QA**：自动测试、Android导出、安装、性能/耗电、触摸实机验收、断网恢复、存档兼容及增量更新验证。编译≠可玩。**尚未完成**。
