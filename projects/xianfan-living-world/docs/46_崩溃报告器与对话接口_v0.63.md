# 闪退不再靠猜：崩溃报告器 + 对白接口

## 一、崩溃报告器（原生）

`CrashHandler` 接管 `UncaughtExceptionHandler`，闪退前写 `files/crash-last.txt`，内容包括：

| 段 | 内容 |
|---|---|
| 头部 | 时间、线程、机型与 Android 版本、应用版本 |
| 现场 | 位置坐标、所在地点、目标、体力/气血、钱、行囊格数、私兵 |
| 最近操作 | 日志里最后 12 条（点人、开背包、装备、御剑…） |
| 堆栈 | 原始栈，第一行就是 `类.java:行号` |

下次启动弹窗：**复制**（进剪贴板，直接粘给开发者）/ 删除 / 留着。文字可选中复制，不依赖任何外部服务。

## 二、自我迭代的前置检查

`native-apk` 工作流新增 `Self-check (tests must be green before building)`：`node --test tests/*.test.mjs` 不过就不出包。也就是说“测试红着发版”这件事从流程上被堵死，不用每次靠人提醒。

## 三、对白接口（`content/dialogue.mjs`，dialogue-0.1.0）

- `smallTalk(npc, ctx)`：性格（warm/cold/sly/plain）× 身份 × 当下情形，确定性拼句，同一人同一天永远同一句，可回放。
- `askWay(npc, target, distance)`：给方向（东南西北）与远近。
- `reply(npc, line, ctx, adapter)`：**给了 adapter 就用模型，没给或抛错就回落模板**。adapter 是 `async ({prompt, persona, ctx}) => string`，本地 llama.cpp / 远端 API 都按这个形状接。

## 四、关于“本地模型”

能接，但不能塞进现在的 APK：

| 方案 | 体积 | 现状 |
|---|---|---|
| 内置 0.5B 量化模型 | 约 300–500 MB | 不可能放进 230 KB 的包，需要独立下载 + JNI |
| 本机 llama.cpp + GGUF | 同上 | 需要编译 JNI、做内存与耗电预算，中端机可跑 3–8 tok/s |
| 远端 API（可选） | 0 | 需要网络与 key，玩家自填 |
| 现在这层模板 | 0 | 已上线，保证“有人能说话” |

真实落地顺序：模板（已做）→ 可插拔 adapter（已做）→ 首次启动下载模型包 → JNI 推理 → 剧情章节用模型生成后本地校验（业力/身份/境界不能越界）。
