# 世界模拟引擎与玩法自然衍生｜系统设计 V0.1

> 本文明确**世界事实如何生成、如何相互影响**。所有数值、规模和接口为设计建议，后续需通过原型测试，不代表已经实现。

## 1. 游戏不是「很多独立小游戏」

最糟糕的设计：经营界面产出虚拟银两，官府界面有另一套抽象粮草，修仙界面再凭空生成丹药与灵石，NPC旁白说自己在行动而数据没有变化。

我们的准则是**实体统一、库存统一、时间统一、位置统一、权限统一、事件可追踪**。

例：玩家救治一个患病农民 → 农民减少缺勤 → 家庭有更多收入 → 粮食销售恢复 → 当地药材需求变化 → 医者名誉变化 → 农民日后可能帮助医者，但不被强制写成报恩任务。此链路不应通过硬编码「接下来触发第二章」实现。

## 2. 数据主权与实体模型

世界核心由不可重复ID定位的实体构成，典型类型：Person / Household / Building / Room / ItemStack / Place / Region / Institution / Position / Route / Contract / Event / Relationship / LegalCase / Market / CultivationResource。

实体数据建议按组件拆分：`Identity`、`Location`、`Ownership`、`Health`、`Inventory`、`Occupation`、`Knowledge`、`Skills`、`Beliefs`、`Goals`、`SocialLinks`、`LegalStatus`、`Cultivation`等。组件缺省意味着实体没有此能力，不必为每块石头保留全套人物字段。

### 2.1 事件示意

```json
{
  "event_id": "evt_00004568",
  "time": 245877,
  "type": "market.trade.executed",
  "actors": ["person_021", "person_497"],
  "place_id": "market_lin'an_east",
  "payload": {"item": "grain_rice", "quantity": 50, "unit": "jin", "payment": 120, "currency": "copper"},
  "causes": ["evt_00004510"],
  "witnesses": ["person_604"],
  "rule_version": "0.1"
}
```

此事件必须与真实交易原子操作匹配：买家余额减少、卖家余额增加、库存转移、手续费或税额按真实政策进入相应账户。若事务未完成，则不得记录交易成功。

### 2.2 事件与「角色知道」分离

权威账本知道市场成交；未目睹的山村人物只能通过行商消息、价格变化或亲自调查获知。对话生成器只能读取该角色允许知道的投影，不直接访问完整世界真相。

## 3. 统一空间：房间级细节与高速修仙旅行不冲突

建立双层空间视图：**现实连续地理坐标（地表距离、河流与高度）＋可交互场所连通图（门、街道、洞府、房间）**。大尺度旅行不需要模拟一百万次房间切换；小尺度交互仍按明确的场所和进入权限进行。

旅行实体包含：起点、终点、路径、移动模式、出发/预计抵达时间、实际速度、消耗、携带质量、地形天气、危险检定、能否中途改变目的地。

| 方式 | 空间尺度 | 约束 | 玩家操作 |
|---|---|---|---|
| 步行 | 房间/街道 → 邻里 | 门锁、路况、体力 | 点击目标、手动探索或自动寻路 |
| 车马 | 县 → 郡 | 道路、坐骑、载重、驿站 | 规划商路、途中处理事件 |
| 船舶 | 河运/海运 | 水文、泊位、天气、港税 | 选择航线和停靠港 |
| 御剑 | 城外/州域/山脉 | 修为、法力、空域、天气、高度、落点 | 大地图选择目的地，飞行进行中可观察地面 |
| 传送阵 | 跨州/跨界锚点 | 阵法、凭证、燃料、稳定性 | 选择已发现的有效节点 |
| 进入洞府 | 室内连通图 | 门/禁制/权限 | 直接展开房间层 |

**示例**：从临安县东市步行到南城门，地图切换为州域；御剑朝青云峰移动，天气导致绕路消耗灵力；途中看见商队遭袭并选择下降；落在道路附近时该商队仍是先前真实出发的商队，不能临时刷新。其财物与护卫与出发前保持连续。

## 4. 时间推进与大规模人口

### 4.1 三级模拟精度

- **精细层（玩家附近/交互相关）**：角色按分钟甚至更细的单位执行移动、对话、生产、战斗和建筑出入；将可观察行动记入事件流。
- **区域层（同县及有交易关系的实体）**：按时段执行家庭预算、职业劳动、货物流转、疾病与治安；仅在需要时展开微观轨迹。
- **宏观层（遥远地区）**：按天、旬或月核算人口变化、运输、价格趋势、财政和势力行为；关键个体仍保持身份和履历，不靠重刷随机NPC假装生活。

精度切换必须守恒。例如商队在宏观层已完成80里路程，玩家御剑赶到后，必须在合理路段生成可观察队伍，不允许从地图中心凭空出现。

### 4.2 调度

优先调度「当前事件时刻最早」的行动，避免每帧遍历全世界所有人。关键系统拥有自己的时间粒度：移动分钟级、职业班次小时级、市场日级、农业季节级、财政月级、年龄年度级。被动变量可以公式补算，真正会改变世界的交易、事故和决定必须记录。

**工程约束**：初版仅1000人口，不预先宣称百万居民能实时逐人推理。建立基准测试后再扩大。叙事层再复杂，也不能让几千名NPC每分钟同时调用语言大模型。

## 5. 经济：所有钱粮必须有来处与去向

资源主要经过：自然禀赋/再生 → 开采/生产 → 加工 → 储存 → 运输 → 交易 → 消费、损耗、积累或回收。

- 田地有面积、土质、灌溉、种子、劳动力和收获季；产量不能由「农民在工作」文字直接产生。
- 家庭有成员、口粮、资产、债务、医疗、税负、衣食居住需要；贫穷具有实际后果但不能简单把所有贫民变为盗贼。
- 商店有房屋、营业时段、库存、资金、供应商、掌柜工资、实际售价。
- 贸易由价格、成本、风险和路线决定；商队真正占用货车、护卫和运力。
- 钱币由发行与税务制度管理，官府税收从家庭或市场账户转移；非法凭空增钱应仅来自合法定义的铸币/事件机制。
- 灵石、符纸、灵材不应取代全部凡俗经济：其购买力、稀缺度、跨界兑换和真假鉴定依实际社会制度确定。

### 5.1 示例：旱灾如何演变为剧情

旱灾 → 村庄减产 → 粮食库存下降 → 粮价上涨 → 民户削减非必需品 → 铁铺订单减少 → 工匠失业 → 县衙决定是否开仓 → 税收或国库变化 → 行商判断是否调粮 → 宗门可能购买粮食援助灾民或继续闭关 → 人物发生相识、冲突与牺牲。

每个箭头都是**数据依赖**，不必写成旱灾任务链。城里是否暴动、谁来赈灾，应由实际条件决定。

## 6. 官制与王朝：职位带来真实权限和责任

### 6.1 官职是权限集合

县令能查看部分官府户籍、签发真实政令、使用规定财政预算、任免规定范围的属官、审理权限内案件；不能凭头衔篡改世界任意数据。户房、刑房、工房、兵房等有分工，具体建制可按架空世界文化与时代配置。

### 6.2 动态仕途

入仕路径包括科举、举荐、军功、权势交易等，不要求所有人走一种路线。成绩、资历、人脉、政绩、利益冲突、舆论和朝廷政策影响任命。腐败是利用权限改变实际财物/判决的事件，可被侦查，也可能长期未暴露。

### 6.3 政务与社会不是两个界面

县令决定修桥：县库减少经费 → 工匠获得订单 → 道路可通行性提高 → 商人运价下降 → 粮食输入成本降低 → 部分家庭命运改变。失败也可能发生：材料不足、贪污、洪水或工期延误。

## 7. 修仙：长生改变所有系统

宗门由独立人员、家产、传承、制度、财源和势力关系组成。修炼需要真实的时间、资源、灵气条件、风险和师承；无法只靠点击按钮抽取修为。飞行与战斗改变交通和政治力量，但应有成本、物资和约束，否则世俗社会会瞬间失去存在价值。

最低限度共享对象：修士也是公民/居民/流动人口，也有出生地、债务、亲属、敌人、资产和法律关系。宗门护山阵法、灵药种植、炼器、商路和赋税会占用土地、消耗物品、影响凡人。

**可衍生问题**：

- 宗门抢占灵脉 → 山村被迫迁徙或获得建设岗位 → 官府调停或出兵 → 家庭关系改变。
- 修士寿元增长 → 祖孙数代与修士同时存活 → 家族的权力、遗产与忠诚发生变化。
- 飞剑物流便利 → 高价值药材跨州交易增加 → 劫匪改换目标 → 城门税收减少，空域法令诞生。
- 仙凡通婚 → 寿元、继承、门规、居住和个人意愿冲突；不得预设唯一结果。

## 8. 战争、司法、治安、宗族与教育的衍生

不是先做一个战争按钮，再给战争添加特效；战争应使用既有**人口、装备、运输、财政、领土、士气、领导权和社会关系**。

- 士兵来自居民，有家庭、农时冲突、军饷、伤亡和返乡生活。
- 军队行军实际占用道路和粮草；打仗会改变商路，推动难民流动。
- 司法从事件证据、人证物证、法律适用和官员权限推导判决；可能误判或被干预。
- 家族由婚姻、出生、收养、继承和共同产业生长，豪族能控制资源但不是自动生成势力值。
- 教育占用时间、学费、老师资源，改变知识与仕途可达性；贫穷家庭需作现实取舍。
- 宗门师承具有传授资格和门规，弟子可能离开；师父不能作为永久静止技能商人。

## 9. 玩法衍生树：基础系统少，交互组合多

以下链条描述「基础条件产生的新玩法」，不是写死任务菜单：

| 基础系统组合 | 自然衍生的玩家体验 | 需要共同账本 |
|---|---|---|
| 人口＋职业＋商品 | 打工、开店、雇佣、竞争、失业 | 工时/收入/库存 |
| 地理＋运力＋物价 | 跑商、护镖、劫道、修路 | 路线/货物/风险 |
| 家庭＋土地＋继承 | 分家、联姻、争产、迁居 | 户籍/财产/法律 |
| 知识＋教育＋官职 | 求学、科举、推荐、任官 | 履历/考试/任命 |
| 官职＋财政＋民意 | 征税、赈灾、工程、弹劾 | 国库/政策/证据 |
| 法律＋社会关系＋证据 | 诉讼、伸冤、包庇、调查 | 案件/证人/权限 |
| 职业＋情感＋事件 | 同袍、知己、婚姻、疏远、背叛 | 记忆/愿望/生活 |
| 灵根＋师承＋资源 | 拜师、修炼、灵药争夺 | 天赋/门规/库存 |
| 运输＋飞行＋禁制 | 御剑护送、空路、截杀、禁飞 | 路径/能量/法令 |
| 寿元＋家谱＋历史 | 百年重访、后代传承、旧物重现 | 生死/继承/史录 |
| 农业＋灾害＋政府 | 赈灾、迁徙、造反、税制改革 | 产量/民户/财政 |
| 王朝＋宗门＋资源 | 护国、封山、边境冲突、修士参政 | 领地/盟约/资源 |

未来扩展应尽量先**丰富已有实体行为与交叉规则**，再增加新模块。新增渔业应连接水域生态、劳动、运输、饮食与税收，而非单独发明一套「捕鱼币」。

## 10. 自发故事与AI的边界

### 10.1 三层叙事

1. **世界事实层**：发生过的行动、位置、交付、结婚、病亡和战争，只有规则引擎有写入权。
2. **角色认知层**：具体人物所见所闻、误解、传闻及个人记忆。
3. **表达层**：用文字、声音或可选本地语言模型，把合法信息组织成自然场景与对话。

语言模型可以把「两人雨夜同车守护病人」讲述得动人，但不能凭空让不存在的病人去世，也不能把NPC的拒绝改成热情答应。

### 10.2 内容生成

程序可组合地方志、商铺招牌、人物姓名、家世习俗与地点特色。动态文本使用结构化事实插槽和语气规则；同一重要事实在不同界面必须一致。世界复杂性由真实模拟而非提示词长度承担。

## 11. 关系＋经济＋政治＋修仙，统一示例

临安县暴发疫病，女医者正在寻药。城里商人有一批药材；县令面临国库短缺；山上宗门拥有一种稀有药草。玩家若是平民，可帮工/跑商/采药；若是县令，可拨款、征用或与商会谈判；若是修士，可借法器运输、向宗门求援。每条路径会影响库存、社会舆论、死亡人数、人物感激或怨恨，而没有所谓「正确路线」必定触发爱情结局。玩家离开后事情照样推进，回来只能面对已经发生的事实。

## 12. 最小状态契约（伪TypeScript）

```ts
type EntityId = string;
type WorldTick = number;

interface EntityLocation {
  entityId: EntityId;
  placeId: EntityId;
  x?: number;
  y?: number;
  altitude?: number;
}

interface RelationshipEdge {
  from: EntityId; to: EntityId;
  familiarity: number; trust: number; respect: number;
  affection: number; safety: number; dependence: number;
  resentment: number;
  sharedEventIds: EntityId[];
  updatedAt: WorldTick;
}

interface EventRecord {
  id: EntityId;
  tick: WorldTick;
  type: string;
  actors: EntityId[];
  placeId?: EntityId;
  causes: EntityId[];
  payload: Record<string, unknown>;
  visibility: 'public' | 'private' | 'restricted';
}

interface TravelPlan {
  actorId: EntityId;
  mode: 'walk' | 'mount' | 'ship' | 'sword' | 'formation';
  fromId: EntityId; toId: EntityId;
  routeId: EntityId;
  departTick: WorldTick;
  progress: number;
}
```

**注意**：此结构只是概念骨架，远不够支撑生产级事务、存储版本、事件溯源和关系隐私。不能因为写了接口就宣称玩法完成。

## 13. 不让性能破坏真实感

核心账本与计算应批处理、按事件唤醒、优先局部精细化；历史存储采用状态快照＋关键事件日志＋可检索索引，避免记录每人每秒的呼吸动作。全量历史可考虑摘要归档，但关乎财产、生命、身份、判决、玩家介入的关键事实不可丢失。

首轮应量测：1000人连续模拟一游戏年，极端时刻的逻辑耗时、存档体积、资源账差、人物丢失率和角色决策稳定性；阈值以设备实测结果制定，不凭空承诺手机可承载上亿人口。

## 14. 研发时优先验证的四条核心因果链

1. **铁匠链**：矿石库存→锻造→成品→销售→货币→税收→家庭消费。
2. **家族链**：相识→独立意愿→建立关系或拒绝→婚姻/分离→财产→下一代。
3. **县政链**：歉收→粮价→百姓消费→县库赈济→商队运粮→治安变化。
4. **修仙链**：灵根→拜师资格→宗门资源→修炼→御剑真实旅行→返回变化后的家乡。

这四条链共享同一世界时钟和事件接口后，再扩充军事、医学、复杂宗教和跨界飞升。
