# 接战前是队列，缠在一起才是混战

## 一、行军与列阵

| 阶段 | 行为 |
|---|---|
| 未接战（`b.mixed=false`） | 每人守自己的**排面**（`rowY`）：横向只做 25% 的微调，纵向才快走；一律朝正前方，队形不散 |
| 一接战 | `mixed=true`，排面松掉；每人带一点个人偏移 `jy`，各自找空隙，队形开始乱 |

判定"接战"的标准是**近战互砍**。弓弩在射程里放箭不算——否则两军还隔着几十米，队形就先散了。

实测：两军相隔约 60 米时全员仍在自己排上（偏离 < 3 米 0 人）；变阵后同一批人偏离超过 3 米的明显出现。

## 二、混战误伤

- 概率 **0.05%**（`FRIENDLY_FIRE=0.0005`），按全战场约 600 人封顶；
- 只在 `mixed=true` 之后才可能发生；
- 近战、法术、箭矢都会误伤：近战砍错人按正常伤害结算，法术会在友军身上炸，箭矢也有概率射到自己人；
- 每次误伤在地图上打一个**橙色小圈**，战报里 `friendly` 记数，HUD 显示"误伤 N"。

按你改的数，900 人的仗打一场大约 800–1900 次挥砍，误伤 0–2 次；**0.05% 是每次攻击的概率上限，不是总伤亡比例**，所以不会出现"自己人砍死自己人一个连"。

## 三、账目变了

`alive` 现在只算**还能打的人**，投降/溃逃的单独计：

```
start = alive + dead + surrendered + routed
```

所以原来的"存活 + 阵亡 = 总数"断言必须改成四段账（已同步改测试）。

## 四、验收

- `node --test tests/*.test.mjs` → **163/163**（新增：接战前排面不散 / 接战后散开、误伤率不超过千分之一）。
- 实拍：`docs/preview/formation-preview.png` 左为行军列阵，右为厮杀混战（同一份战况数据渲染）。

## 五、没做的

- 队形只有"方阵/横阵/楔形"三种列位，没有真正的骑兵包抄、弓手撤到后阵；
- 混战只是"排面散开"，没有刀牌手顶前线、长枪在后压阵的分层；
- 误伤没有区分兵种（弓手乱射和高阶修士的范围术法应差很多）；
- 大规模（数千人）一场推演要几十秒，还没做分帧/降采样。
