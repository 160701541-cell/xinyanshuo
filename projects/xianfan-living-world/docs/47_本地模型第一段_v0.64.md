# 本地模型：先把「取模型」和「用模型」拆开

用户选了「首次启动下载小模型（约 300–500MB）」。这件事必须分两段做，否则会变成“下完没变化”。

## 一、这一段真的落了什么

| 件 | 状态 |
|---|---|
| 模型下载器（`ModelStore`） | 完成：398MB GGUF、断点续传（HTTP Range）、进度百分比、落 `files/models/` |
| 下载入口 | 完成：首次启动询问一次，可选「下载 / 以后再说 / 不再提示」；已下载则跳过 |
| 对话界面 | 完成：底部「对话」页，输入一句话，显示对白与来源（模型 / 模板） |
| 推理桥（`LlmBridge`） | 骨架：`System.loadLibrary("xf_llm")` 失败即视为不可用，**绝不假装能生成** |
| 对白回落 | 完成：`talkWith()` 模型返回 null 就走原来的街谈，任何异常都不崩 |

## 二、还没落地的那一半（下一段）

- llama.cpp 的 Android 编译（arm64-v8a）与 JNI 封装 `nativeGenerate(modelPath, prompt, maxTokens)`。
- 编译产物进 `jniLibs/`，APK 会从 244 KB 涨到约 3–5 MB。
- 首次加载模型的内存预算（0.5B q4 约需 500–700MB 常驻，低端机要降级到 256 上下文）。

**因此这一版的弹窗会明说**：推理内核还没编进来，下完仍走模板，可等下一版启用。宁可说清楚，也不让玩家下 400MB 后觉得被骗。

## 三、为什么不现在硬编进去

CI 里编译 llama.cpp + NDK 需要 10–15 分钟且极易因上游 API 变动失败；把它和玩法包解耦，主包才能继续每轮快速发。下一段单独做，失败也只影响模型功能，不影响能玩。

- CI：`native-apk` 通过（编译期已验证 `ModelStore`/`LlmBridge`/对话页）。
- 未做：JNI 编译、模型加载、流式输出、剧情章节生成。
