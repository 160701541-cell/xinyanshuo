# 卡片也变成数据：界面不再自己挑字段

上一版引擎已经能描述“什么时候触发什么后果”，但地图上的地点卡、建筑卡、人物卡还是手写的 HTML——加一张卡就得改渲染函数。这一版把最后一层也交出去。

## 一、现在一张卡长什么样（`content/cards.mjs`）

```js
{
  id: 'poi-structure', kind: 'poi',
  fields: [
    {key:'name', label:'建筑'},
    {key:'open', label:'营业'},
    {key:'access', label:'通行'},
    {key:'near', label:'门前'},
    {key:'desc', label:'说明'}
  ],
  actions: [
    {id:'go', label:'沿路前往门口', when:{path:'canGo', op:'truthy'}},
    {id:'enter', label:'从正门进入', when:{path:'canEnter', op:'truthy'}},
    {id:'stop', label:'停下', when:{path:'traveling', op:'truthy'}}
  ]
}
```

- **字段**带 `when`：人口为 0 的地点卡不会显示“人口：0”，灵根未测的人物卡不会显示“灵根”；
- **动作**带 `when`：离得远就没有“从正门进入”，没有在赶路就没有“停下”；
- 四个模板：`poi-place`（地点/地标/野外地面）、`poi-structure`（建筑）、`person-card`（人物）、`event-card`（事件）。

## 二、界面只做三件事

`showSheet()` 现在只负责：算一次上下文（距离、营业、通行、门前有谁）、`cardView(w, tplId, ctx)` 拿行与按钮、把结果摆进 DOM。点击交给 `sheetAction(id)` 派发——**模板说“有什么按钮”，代码说“按钮做什么”**。

这意味着：改文案、加字段、加按钮、换条件，都是改 `content/cards.mjs`，不用碰 `overworld-ui.mjs`。

预览：`docs/preview/card-sheet.png`

## 三、验收

- `node tools/content-lint.mjs` → `16 条规则 / 4 张卡片`
- `node --test tests/*.test.mjs` → **195/195**
- 卡片条件测试：人口 0 不显示人口行、无路可走不出现“前往”、未加载模板返回 `null`。

## 四、还没做

- 规则仍按数组顺序跑，没有权重与互斥；
- “为什么触发这条”的可读因果还没进卡片（只有纪事文案）；
- 内容改了 id 会让老存档的 `fired` 对不上，需要一次迁移；
- 卡片还没有图标位（现在只有文字行），要等图标素材那一批。
