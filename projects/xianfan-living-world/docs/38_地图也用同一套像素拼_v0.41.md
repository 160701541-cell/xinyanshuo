# 地图也试过了：同一套积木，拼出一整座县城

你说“美术风格就定这种，试试地图能不能这样拼”——能。现在**地图近景和卡牌背景是同一套配方、同一份色板**。

## 一、怎么拼

`content/townart.mjs`，4 米一格，县城 ±840 米 = **420×420 格**：

| 积木 | 干什么 |
|---|---|
| `Grid.roof()` | 俯视瓦顶：瓦垄、正脊、檐口，带 1 格落影与檐下暗边 |
| `Grid.tree()` | 三层圆的树冠（深/中/亮） |
| `Grid.well()` | 井台与井水 |
| `Grid.lineTo()` | 按米铺街：先铺路肩，再铺路面，大街加一道车辙 |
| `frame()` | 院墙（夯土）与城墙（带垛口） |

顺序也是真的：**草皮打点 → 城外田块 → 河与岸 → 街 → 院落（墙、屋、门、井、树）→ 城墙与城门**。所以街不会被院子压掉，城门是对着大街的。

## 二、和卡牌共用色板

卡牌背景用 `roof/wood/water/tree` 那套；地图用 `roofTile/thatch/street/cityWall` 同一批色相。两边都是 4 米或 1 米感官上的同一支笔，所以**点开卡片看到的客栈，和地图上那间客栈是同一种画法**。

## 三、游戏里怎么用

`overworld-ui.mjs` 新增 `bakeTown()`：第一次走近县城（<14 米/像素）时把整张 420×420 烘焙成离屏画布，之后按世界坐标直接贴图。

- 烘焙一次 **65 毫秒**（176,400 格），只在首次进近景时发生；
- 之后每帧只是 `drawImage` 一次，不在逐帧算格子；
- 远景（>14 米/像素）仍走原来的地形色块，避免 420 格在城市远景里变成噪点。

## 四、验收

- `node --test tests/*.test.mjs` → **207/207**
- 新增 6 项：格宽与版本、两次烘焙完全一致、城墙/垛口/街面/屋顶真的在地图上、城外是田与草、没有 undefined 色、田园配色不重复。
- 预览：`docs/preview/town-pixel.png`（全城 1245px）、`docs/preview/town-pixel-zoom.png`（中心放大）

## 五、还没做

- 俯视屋顶只有“两坡”一种，没有转角与院落错落；树是一团，没有竹、柳之分。
- 街上没有摊位、招牌、行人（行人是另一层画布画的，不在烘焙里）。
- >14 米/像素时仍切回色块地形，中间那一档会有一次“风格跳变”，需要过渡。
- 城池外的村落、宗门山门还没有用这套积木拼。
- 没有实机截图：本机无浏览器，预览图是同源数据离线渲染。
